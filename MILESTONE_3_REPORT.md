# Sovereign AI Workbench — Milestone 3 Report
## Feature Branch: `feature/knowledge-rag`

### Objective
Implement the Local Knowledge Base and RAG (Retrieval-Augmented Generation) subsystem, enabling users to index internal documents and query them locally while preserving strict air-gap and data privacy constraints.

### Core Achievements
1. **Fully Local & Air-gapped Knowledge Pipeline**: No network borders are crossed. Vectors are generated within the same process; indexing and storage all occur in short-term RAM, adhering to the Sovereign AI promise.
2. **TF-IDF Embedding Engine**: Given strict local-only network constraints and repeated connection timeouts during `sentence-transformers` installation attempts, a fallback approach using `scikit-learn`'s `TfidfVectorizer` was successfully engineered. This produces dense normalized vectors supporting cosine similarity without PyTorch, model weight downloads, or GPUs.
3. **Advanced Chunking Strategy**: The knowledge extraction system maps source documents to overlapping text chunks (`chunk_size=800, chunk_overlap=100`) while preserving essential provenance variables: `document_id`, `filename`, `page_number`, and `section`. ASHA-256 is used recursively for declarative, deterministic chunk ID generation preventing duplication. 
4. **Citation Management**: Responses generated by the Gemma 3 LLM are strictly grounded on indexed evidence, appending verifiable deduplicated citations (`[Source: filename, Page: X, Section: Y]`).

### Architectural Evolution
The new infrastructure encapsulates multiple services inside `backend/app/knowledge/`:
- **Models (`models.py`)**: `KnowledgeDocument`, `KnowledgeChunk`, `RetrievalResult`, and structured responses (`Citation`, `RAGResponse`).
- **Embedding Provider Abstract Block (`embeddings.py`)**: Designed to seamlessly intercept TF-IDF and upgrade to PyTorch-based neural embeddings in the future.
- **In-Memory Store (`memory_store.py`)**: Leverages vectorized Numpy dot products over sparse L2 projections.
- **Ingestion & Retrieval Pipelines (`ingestion.py`, `retrieval.py`)**: Seamless chunk handling, embedding batched pipelines, and deterministic metadata linking context and extraction boundaries.
- **RAG Generation (`rag_service.py`)**: Injects strict boundaries onto the `LlamaCppProvider` restricting the model's predictive tokens exclusively to retrieved evidence to halt hallucinations effectively.
